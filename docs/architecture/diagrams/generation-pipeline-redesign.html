Generation Pipeline Redesign

Same pipeline shape, re‑pooled to pull THINKER calls out wherever a GENERATOR‑pool loop with explicit feedback can stand in for a one‑shot strong‑model judgment.

The bet: weak model + a specific, applied correction + iteration ≈ strong model in one shot — everywhere except the one place a wrong verdict silently ships bad content with no downstream check: gate pass 2. That stays THINKER. Decisions taken: curriculum verifier runs on GENERATOR; gate pass 1 stays THINKER for the first gate pass and drops to GENERATOR only for the redraft loop (the Run 6 anomaly — THINKER out‑spent GENERATOR because it ran the corrector and the verifier every round); all moves land together.

Open threads before this is buildable

  • New ContentGenerator methods — verify_curriculum, revise_curriculum, verify_questions, each batched (ADR‑0005). correct_cards is called with the THINKER governor on a batch’s first gate pass and the GENERATOR governor on every redraft round — the call site chooses, the method is pool‑agnostic. verify_cards’ output schema gains suggested_fix and an unfixable flag.
  • The curriculum verifier’s rubric is the whole ballgame — coverage completeness, tier coherence, subtopic non‑overlap. Budget arithmetic stays a code check (trusted for taste, not constraints).
  • Loop A vs loop B routing — verify_cards must reliably tell “change the 1953 date to 1955” (loop A) from “the premise is wrong, scrap it” (loop B). A vague fix instruction is what makes the lite corrector fumble.
  • Convergence guards — reuse _redraft_until_bar’s existing pattern (N consecutive unproductive rounds, REJECTED vs FAILED counted apart) for both new loops; no blind round caps.
  • ADR trail — amends 0007 (curriculum SPOF mitigation now “strong model for the first pass”), 0028/0029 (pool assignment), 0030 (pass 1 pool + verifier authors fixes), 0031 (feedback loop extends to curriculum and questions), 0059 (planner role expands). Likely one new ADR for the re‑pooling plus amendments to those.
