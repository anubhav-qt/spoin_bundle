## Game AI Decision Architectures: FSMs, Behavior Trees, and Utility Systems
Non-player character (NPC) artificial intelligence in video games focuses on believability, responsive decision-making, and performance under strict real-time frame budgets. The historical foundation of game AI is the **Finite State Machine (FSM)**, where an agent occupies a single discrete state (`Patrol`, `Investigate`, `Attack`, `Flee`) and evaluates explicit transition rules every tick. While simple and deterministic, FSMs suffer from combinatorial explosion as entity complexity grows: adding a new state requires wiring transitions to and from existing states, creating fragile spaghettis of logic. To address this, modern commercial game AI relies predominantly on **Behavior Trees (BT)**. A behavior tree is a directed hierarchical tree evaluated from root to leaves at regular intervals, returning `SUCCESS`, `FAILURE`, or `RUNNING`. Execution flow is directed by composite nodes: **Sequences** execute children in order and fail immediately if any child fails (functioning like logical AND, ideal for multi-step tasks like `FindAmmo -> MoveToAmmo -> Reload`), while **Selectors** execute children in order and succeed immediately if any child succeeds (functioning like logical OR, ideal for fallback choices like `AttackMelee -> AttackRanged -> TakeCover`). Decorator nodes wrap children to enforce condition checks or timers, while a centralized shared memory dictionary called a **Blackboard** stores tactical world states (such as `TargetEnemy` or `AlertLevel`). For highly emergent, non-scripted behaviors (such as companion NPCs or simulation games like *The Sims*), **Utility AI** models evaluate mathematical response curves across competing candidate actions, scoring choices dynamically based on hunger, danger, and social proximity to select the optimal behavioral output.

## Spatial Navigation and Pathfinding: NavMeshes and the A* Algorithm
Once an AI agent selects a destination, it must navigate the complex geometric world without colliding with walls, falling off ledges, or becoming trapped in geometry. Modern engines represent walkable terrain using a **Navigation Mesh (NavMesh)**. A NavMesh is a continuous, simplified polygonal mesh composed of connected 2D or 3D convex polygons that blanket all traversable surfaces, generated through automated voxelization and contour extraction from the level's static collision geometry. Because any straight line within a convex polygon is guaranteed to be unobstructed, agents pathfind between polygon portals rather than navigating raw point grids. Pathfinding across the NavMesh is computed using the **$A^*$ (A-Star) Search Algorithm**. $A^*$ operates on a heuristic evaluation function $f(n) = g(n) + h(n)$, where $g(n)$ represents the exact path cost accumulated from the start node to current node $n$, and $h(n)$ is an admissible heuristic estimate (such as Euclidean or Manhattan distance) of the remaining distance from $n$ to the goal. By prioritizing nodes with the lowest total estimated cost $f(n)$ using a min-heap priority queue, $A^*$ guarantees discovering the shortest path while exploring a minimal subset of graph nodes. At the local movement level, agents utilize Craig Reynolds' **Steering Behaviors**—combining kinematic force vectors for seeking, fleeing, arrival, obstacle avoidance, and flocking (cohesion, separation, alignment)—to smoothly follow path waypoints and dynamically dodge moving obstacles.

## Multiplayer Network Topologies: Peer-to-Peer vs. Authoritative Client-Server
Real-time multiplayer games must synchronize state across geographically separated machines connected over the non-deterministic, high-latency public internet. In a **Peer-to-Peer (P2P)** network topology, each participating player's machine connects directly to every other player, transmitting local inputs or state updates. While P2P eliminates the operational expense of dedicated server infrastructure, it is fundamentally vulnerable to competitive exploitation: because each client acts as an authority, malicious players can easily tamper with local memory to alter health, teleport, or inspect hidden information; furthermore, network bandwidth scales quadratically with player count, and games suffer from "host advantage" or desynchronization. Modern competitive multiplayer games universally adopt the **Authoritative Client-Server Architecture**. In this model, a dedicated, trusted server process acts as the single, indisputable arbiter of truth. Clients run local simulations solely for input collection and visual presentation; player keystrokes and gamepad inputs are transmitted to the server over the network. The server receives client inputs, validates them against physical and game rules, steps the master simulation forward by a fixed server tick, and periodically broadcasts authoritative world state snapshots back to connected clients. By centralizing physics and logic on the server, authoritative architectures eliminate speed hacks, impossible collisions, and data fabrication.

## Latency Compensation: Client-Side Prediction and Server Reconciliation
While authoritative client-server architecture eliminates cheating, it introduces a severe psychological barrier: input latency. If a client transmits a keystroke to a server located 50 ms away, the server requires 50 ms to receive the input and another 50 ms to send the resulting position snapshot back to the client—yielding a 100 ms Round-Trip Time (RTT). If a player experiences a 100 ms delay between pressing the jump key and seeing their character leave the ground, controls feel unplayably sluggish and unresponsive. Formalized by Gabriel Gambetta, modern games eliminate this latency through **Client-Side Prediction (CSP)** and **Server Reconciliation**. Under Client-Side Prediction, when the local player presses an input, the client does not wait for server authorization; it applies the movement to the local simulation immediately, rendering the character moving on the very next local frame. To maintain consistency, the client stores a circular buffer of unacknowledged inputs alongside their resulting predicted historical states. When an authoritative server snapshot eventually arrives, the client verifies whether the server's acknowledged position matches its past predicted position for that specific tick. If a discrepancy exists (caused by packet loss, an unforeseen collision with an opponent, or external forces), **Server Reconciliation** snaps the local player to the authoritative server position and instantly re-simulates all subsequent unacknowledged inputs in the buffer to bring the character up to the current frame seamlessly. For shooting mechanics, servers implement **Lag Compensation (Server Rewind)**: when a client fires at tick $T$, the server rewinds all enemy hitboxes back to where they physically resided at tick $T$, verifying whether the shot hit the target as it appeared on the shooter's screen before stepping time forward again.

## Deterministic Simulation and Rollback Netcode (GGPO)
In fast-paced, frame-critical genres—most notably competitive fighting games like *Street Fighter* and *Guilty Gear*, as well as real-time strategy (RTS) titles—even small visual reconciliation pops or traditional input delays are competitively unacceptable. Historically, fighting games relied on **Delay-Based Netcode**, which artificially delays local button execution by a fixed number of frames (e.g., 3 to 6 frames) while waiting for the remote opponent's inputs to arrive over the wire; when network latency spikes, the game freezes or drops inputs, destroying precision combos. The modern gold standard is **Rollback Netcode**, popularized by Tony Cannon's open-source **GGPO** (Good Game Peace Out) architecture. Rollback netcode operates on an uncompromising principle: local player inputs execute with zero added delay on frame 0. When simulating the next frame, if the opponent's input has not yet arrived across the network, the engine predicts that the opponent is holding their most recent input. If the opponent's true input subsequently arrives and matches the prediction, simulation proceeds without interruption. If the opponent changed inputs (e.g., executing a surprise block or reversal), the engine executes an instantaneous **Rollback**: it restores the deterministic game state to the exact frame where the divergence occurred, injects the true remote input, and re-simulates all subsequent frames forward to the present within a fraction of a millisecond. Provided the game logic is fully deterministic (isolated from unseeded random numbers and floating-point non-determinism) and simulation state can be snapshotted and restored rapidly, rollback netcode produces an online multiplayer experience that feels completely indistinguishable from playing locally on the same physical console.
