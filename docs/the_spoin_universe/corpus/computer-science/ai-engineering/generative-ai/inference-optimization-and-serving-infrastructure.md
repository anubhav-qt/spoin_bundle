## The Physics of LLM Inference: Memory-Bound vs. Compute-Bound Regimes
To optimize Large Language Model serving, systems engineers must first analyze the fundamental physics governing transformer inference. LLM execution bifurcates into two radically distinct computational phases: the **Prefill Phase** (processing the prompt) and the **Decoding Phase** (autoregressively generating output tokens). During the Prefill Phase, the model processes all input prompt tokens concurrently. Because all tokens interact simultaneously through self-attention and feed-forward layers, this phase is highly parallelizable and exhibits high arithmetic intensity (the ratio of floating-point operations performed per byte of memory accessed from High Bandwidth Memory). Prefill fully saturates GPU Tensor Cores and is fundamentally **compute-bound**. In contrast, the Decoding Phase operates autoregressively, generating tokens sequentially one by one. To generate a single output token, the GPU must stream every single weight of the neural network from off-chip High Bandwidth Memory (HBM) across the memory bus into on-chip SRAM registers. For a 70-billion parameter model in 16-bit precision (requiring 140 gigabytes of weights), emitting just one token requires reading 140 GB across the memory bus. On an NVIDIA H100 GPU possessing 3.35 terabytes per second of memory bandwidth, the theoretical physical upper limit for single-stream generation is approximately $3,350 / 140 \approx 24$ tokens per second. Consequently, autoregressive decoding exhibits an abysmal arithmetic intensity and is fundamentally **memory-bandwidth-bound**. Effective serving optimization therefore focuses on maximizing memory bus saturation via batching, minimizing redundant memory traffic through kernel fusion, and compressing parameter footprints.

## Attention Kernel Acceleration: FlashAttention-3 and FlashInfer
At the algorithmic level, accelerating the transformer's core computational bottleneck requires optimizing attention kernels across the GPU memory hierarchy. A modern GPU features two primary storage tiers: massive but relatively slow off-chip High Bandwidth Memory (HBM: 80 to 192 gigabytes, transferring at 3 to 8 TB/s) and ultra-fast but scarce on-chip Shared Memory / SRAM (roughly 20 to 50 megabytes, transferring at 30 to 50 TB/s). Standard self-attention implementations instantiate intermediate attention matrices ($S = QK^T$ and $P = \text{softmax}(S)$) directly in HBM, generating $O(N^2)$ memory reads and writes that overwhelm the memory bus on long sequences. Tri Dao's **FlashAttention** revolutionized this by introducing tiling and online softmax. By partitioning query, key, and value matrices into blocks that fit entirely within SRAM, FlashAttention computes exact attention incrementally while dynamically updating running softmax normalization constants, completely eliminating quadratic HBM read/write round-trips. Building on this, **FlashAttention-3** (optimized for Hopper H100) and **FlashAttention-4** (for Blackwell B200) exploit asynchronous hardware primitives such as the Tensor Memory Accelerator (TMA) and warp-specialization. These kernels overlap data movement from HBM to shared memory concurrently with Tensor Core matrix multiplications, delivering up to $2\times$ throughput improvements over FlashAttention-2. In modern production serving engines like vLLM and SGLang, **FlashInfer** provides specialized, page-aware attention kernels optimized for Multi-Head Latent Attention (MLA) and block-sparse decoding, maintaining peak throughput under irregular, dynamically expanding context lengths.

## Dynamic Memory Management: PagedAttention and vLLM
In production serving clusters, the primary barrier to high concurrency is not raw compute, but catastrophic GPU memory fragmentation caused by the Key-Value (KV) cache. In traditional naive serving runtimes, systems statically pre-allocate a contiguous memory buffer for each incoming request sized to the model's theoretical maximum context length (e.g., reserving 8,192 tokens of KV memory even if a request only generates 400 tokens). This leads to between 60% and 80% of GPU memory being wasted due to internal fragmentation (unused reserved slots) and external fragmentation (inability to pack non-uniform buffers). In 2023, Woosuk Kwon and UC Berkeley researchers resolved this with **PagedAttention**, the core engine behind **vLLM**. Inspired by virtual memory and paging in classical operating systems, PagedAttention partitions the KV cache of each sequence into fixed-size physical memory blocks (typically holding 16 or 32 tokens). A centralized Page Table maps logical token positions to non-contiguous physical blocks scattered across GPU VRAM. When new tokens are decoded, new physical blocks are allocated dynamically on-demand, eliminating fragmentation and pushing memory utilization past 96%. This near-perfect memory packing unlocks a $2\times$ to $4\times$ increase in request concurrency on identical hardware. PagedAttention also enables crucial production primitives: **Continuous Batching** (iteration-level scheduling where newly arrived requests immediately join running batches), **Chunked Prefill** (splitting massive prompt prefills into chunks to prevent decoding latency spikes), and **Prefix Caching** (sharing identical system prompt KV blocks across thousands of independent user sessions).

## Speculative Decoding and Multi-Token Acceleration
Because single-stream autoregressive decoding is inherently memory-bandwidth-bound, standard execution leaves the massive parallel compute capabilities of GPU Tensor Cores largely idle. **Speculative Decoding**, formulated by Yaniv Leviathan and colleagues, fundamentally breaks this sequential bottleneck by trading surplus compute for memory bandwidth efficiency. Speculative decoding couples a large, high-capability "Target Model" (e.g., a 70B parameter LLM) with a small, ultra-fast "Draft Model" (e.g., a 1B to 3B parameter model). During each iteration, the lightweight draft model quickly autoregressively generates $K$ candidate tokens (typically $K \in [3, 6]$). The large target model then evaluates all $K$ candidate tokens concurrently in a single, parallel forward pass. Because evaluating $K$ existing tokens simultaneously is compute-bound rather than memory-bound, the target model verifies the entire sequence in nearly the exact same wall-clock time required to generate a single token. A modified rejection sampling mechanism compares the draft and target probability distributions: all tokens matching the target distribution are accepted; upon the first divergence, the incorrect draft token is discarded, the target model's true next token is emitted, and the draft model restarts from the verified prefix. Speculative decoding achieves an empirical $2\times$ to $3\times$ end-to-end wall-clock speedup with mathematically guaranteed zero loss in output quality. Frontier systems advance this paradigm further: **EAGLE-3** generates speculative drafts directly from the target model's internal hidden states without requiring an auxiliary draft model, while DeepSeek-V3 pre-trains native Multi-Token Prediction (MTP) heads that serve as built-in speculative drafters.

## Quantization Spectra: From INT4 and FP8 to Native Blackwell FP4
The final frontier of serving infrastructure optimization is numerical precision quantization—compressing weight and activation bit-widths to slash memory bandwidth consumption and maximize Tensor Core throughput. Modern post-training quantization (PTQ) has evolved far beyond naive uniform integer rounding. In 4-bit integer quantization, **AWQ (Activation-aware Weight Quantization)** recognizes that not all weights are equally critical; by analyzing activation distributions, AWQ protects the top 1% most salient weight channels in higher precision while quantizing the remaining 99% into 4-bit integers, preserving reasoning capabilities without retraining. Concurrently, **FP8 (8-bit Floating Point)** formats—specifically E4M3 (1 sign, 4 exponent, 3 mantissa bits) for activations and weights and E5M2 for gradients—have become the native standard across NVIDIA Hopper and Ada Lovelace architectures. FP8 cuts memory footprint by 50% relative to 16-bit formats and doubles mathematical throughput while maintaining virtually identical perplexity across models up to hundreds of billions of parameters. At the architectural vanguard, NVIDIA's Blackwell architecture (B200 / GB200) introduces second-generation Transformer Engines supporting native **FP4 (4-bit Floating Point)** Tensor Cores. Utilizing microscopic two-level scaling factors across small blocks of numbers, native FP4 provides double the compute density and memory bandwidth efficiency of FP8. This hardware-software co-design allows trillion-parameter Mixture-of-Experts architectures to run high-throughput inference across compact GPU clusters that previously required multi-rack supercomputer infrastructure.
